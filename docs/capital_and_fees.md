# (b) 資金制約と手数料：提案と比較

資金 **200万円** で寄り引け（前日売買代金TOP20・1日で寄り→引け）を回す際の現実的な建て方と、
手数料でどれだけ負けるかの比較。`oc_strategy/sizing.py` ＋ `scripts/run_oc_cost_compare.py` で再現できる。

```bash
python scripts/run_oc_cost_compare.py --capital 2000000
# 出力: results/oc_cost_compare.csv / .png
```

---

## 問題の核心
1. **値がさ株が買えない**：単元(100株)だと 4–5万円株は 1単元=400–500万円。200万では 1単元すら買えず、
   20銘柄均等は不可能（動画でも「1日2,3銘柄」L290–301）。→ **銘柄数が減り、シグナルを再現できない（sizing_drag）**。
2. **デイリーの寄り引け＝年約252回の往復売買**。→ **1往復あたりの手数料が小さくても 252倍に効く（fee_drag）**。
   - ざっくり `年間手数料drag ≈ (買率＋売率＋スプレッド×2) × 252`。0.1%/往復でも ≈ 25%/年。

劣化を2要因に分けて評価する：**sizing_drag（制約）** と **fee_drag（手数料・スリッページ）**。

## 建て方の選択肢と提案

（手数料・約定仕様は 2026-06 の web 調査ベース。改定がありうるので要再確認）

| 方式 | 空売り | 寄り→引け約定 | 200万での分散 | 手数料 | 評価 |
|---|---|---|---|---|---|
| **単元＋一日信用（両建）** | ✅可 | ✅可（ザラ場OK） | ✗ 数銘柄に集中 | 大手**売買0円**＋スリッページ | ◎ **戦略に最も忠実**（ショート維持）。集中はリスク |
| 単元＋現物（ロングのみ） | ✗ | ✅可 | ✗ 集中 | 通常手数料 | △ ショート喪失で**符号が反転し負けに転落**しうる |
| **端株 SBI S株** | ✗ | ✅可（約定9:00/12:30/15:00） | ✅ 多銘柄 | **売買0円** | ◎(long専用) 0円＋寄り引けロング再現可 |
| **端株 moomoo ひと株** | ✗ | ✅可（翌前場始値で買い＋後場引値で売り） | ✅ 多銘柄 | **売買0円** | ◎(long専用) 0円＋寄り引けロング再現可 |
| 端株 楽天かぶミニ | ✗ | △ 寄付のみ=引け売り不可 / RTは可 | ✅ | 寄付0円・**RTは片道0.22%** | ✗ RTは往復0.44%×252≈111%/年で壊滅、寄付は引け売れず |
| 端株 マネックス ワン株 | ✗ | ○ | ✅ | 買0/**売0.55%**(最低52円) | ✗ 往復で手数料倒れ |

### 提案（推奨）
- **本命：単元＋一日信用**。空売りを維持できるのでショート側（画像で稼ぎ頭）を捨てずに済む。
  手数料0円の証券会社（大手のデイトレ信用）を使い、コストは主にスリッページ。
  200万では集中するので、**銘柄数とサイズの制約をそのままフォワードに織り込む**（このモジュールが対応）。
- **端株は「ロング専用の安価な分散版」**として“別戦略”扱い。**SBI S株 / moomoo ひと株（ともに売買0円）一択**。
  両社とも約定タイミング上、**寄り引けのロング側は再現可能**（SBI=9:00買い・15:00売り／moomoo=翌前場始値買い・当日後場引値売り）。
  ただし **単元未満株は信用取引不可＝空売りできない** → 戦略が long-only に変質し、画像で稼ぎ頭だった
  「米国下落翌日のret1/ret5ショート」を取りこぼす。
- **%課金の端株（楽天かぶミニRT 0.22%・マネックス売0.55%）はデイリー寄り引けには不可**（手数料倒れ）。
  楽天かぶミニの寄付取引は無料だが寄付のみ＝引けで売れず寄り引け不可。
- 手数料が重いなら、**売買頻度を落とす／一部を翌日持ち越す**等で年間往復回数を減らすのが効く。

## 比較の見方（合成データでの例）
`fee_drag(%pt/yr)` が「手数料そのもの」で負ける量。`sizing_drag` は「制約（銘柄数・単元丸め・ショート不可）」で負ける量。

合成サンプルでの傾向（**実データでないので絶対値に意味はない／構造だけ見る**）：
- 一日信用（スリッページ3bps仮定）→ fee_drag ≈ 15%pt/yr。**わずかな滑りでも往復252回で巨大化**。
- 端株 %課金（0.22–0.55%）→ fee_drag 80–94%pt/yr。**完全に手数料倒れ**。
- 端株 実質0（SBI S株／moomoo=0想定）→ fee_drag ≈ 0。ロング専用ぶんの差（sizing_drag）だけ。

## moomoo（web調査で判明）
- **ひと株（単元未満株）は売買手数料0円**。
- 約定は1日2回：**13:00までの注文＝当日後場引値**／**17:30以降の注文＝翌営業日の前場始値**。
  → 「夜に買い注文（翌前場始値=寄り）」＋「翌日13時までに売り注文（当日後場引値=引け）」で**寄り引けロングを再現可能**。
- **日本株は信用取引不可（保証金にも使えない）＝空売り不可**。→ ロング専用。
- 結論：moomoo は **0円かつ寄り引けロング再現可**で、SBI S株と並ぶ最良の long-only 選択肢。ただし**ショートは取れない**。

## 端株(long-only)に変質したときの取り分の分析
端株（SBI/moomoo）は **空売り不可 → 戦略が long-only に変質**する。どのシグナル/レジームが
long-only で生き残るかを `side(両建/ロング/ショート)` に分解して評価できる。

```bash
python scripts/run_oc_longonly.py
# 出力: oc_side_decomposition.csv / oc_longonly_best.csv / oc_longonly_curves.png
```
- `oc_side_decomposition.csv`：特徴量 × 市況 × side の 年率/SR/最大DD/勝率。
  **ショート行**を見れば「空売りを失うと何を捨てるか」が分かる（画像では米国下落翌日の ret1/ret5 が稼ぎ頭）。
- `oc_longonly_best.csv`：long-only を SR 降順に並べた採用候補。先頭が端株運用の推奨シグナル/レジーム。
- SR は配分スケールに依存しないので side 間で公平に比較できる（年率は各 side 満額投資の想定）。

→ 端株で行くなら、この表の long 行トップの `SIGNAL_FEATURE` / `MARKET_REGIME` を `config.py` に設定する。
