# ショート可（単元＋一日信用）vs ミニ株（端株・long-only）

寄り引け戦略を 200万円で回す際の 2 方式の違い。`scripts/run_oc_cost_compare.py` と
`scripts/run_oc_longonly.py` で実データの数値比較ができる（手数料・約定仕様は 2026-06 調査）。

## 一覧

| 観点 | **A. 単元＋一日信用（両建）** | **B. ミニ株／端株（SBI S株・moomoo, long-only）** |
|---|---|---|
| 空売り | ✅ 可（戦略フル） | ❌ 不可（信用×）→ **ロング専用に変質** |
| 戦略の取り分 | 画像の稼ぎ頭 **米国下落翌日の ret1/ret5 ショート(SR1.16/1.45)** を取れる | その**ショートの取り分を放棄**。OC など long でも残る分のみ |
| 約定 | ザラ場でリアルタイム → 寄り/引けを正確に約定 | 1日数回の成行のみ（SBI 9:00/12:30/15:00／moomoo 翌前場始値・後場引値）。寄り引けロングは再現可・指値/細かい板操作は不可 |
| 手数料 | 大手の一日信用は**売買0円**。コストは主にスリッページ | SBI S株・moomoo ひと株は**売買0円**（楽天RT0.22%・マネックス0.55%は手数料倒れで不可） |
| 分散（200万で） | ✗ 値がさ株の単元が買えず **1日2〜3銘柄に集中**＝シグナル再現できない | ✅ 1株単位で **20銘柄に均等分散**＝ロード側シグナルをほぼ忠実に再現 |
| 個別銘柄リスク | 大（集中） | 小（分散） |
| 下方リスク | ショートは**理論上損失無限**＋踏み上げ・逆日歩/貸株料・追証 | 現物ロングのみ＝**損失は投資額まで**。追証/逆日歩なし |
| 売り禁(RestrictedByJSF) | 影響あり（売り禁銘柄は空売り不可→その分ロング/スキップ） | 無関係（ショートしないので） |
| 口座・手間 | 信用口座審査・建玉/当日決済管理・追証監視 | 信用口座不要・建玉管理不要・シンプル |
| 必要資金との相性 | 単元20銘柄分散には数千万必要。小資金では集中前提 | 小資金(200万)と好相性 |

## パフォーマンスへの含意
- 画像より **ret1/ret5 は米国下落翌日(down)で高SR**＝下げ後の逆張り。down の主役がショート側なら、
  long-only だと down レジームの取り分が薄くなる。
- **OC(寄引)は両レジーム・long/short 両方プラス**なので、long-only でも比較的残りやすい（要実データ確認）。
- ネット = グロス × (1−コスト) − sizing劣化。
  - A：戦略フルだが **集中(sizing_drag大)＋ショートのリスク/コスト**。
  - B：**0円・フル分散・下方限定**だが **long-only の機会損失**。

## 提案（資金フェーズ別）
1. **小資金(〜数百万)＝まず B（ミニ株 long-only）**：集中リスクと無限損失を避け、0円・分散で安全に検証。
   `run_oc_longonly.py` の long 行トップ（OC や ret1 の long が候補）を採用。
2. **資金増（単元で20銘柄分散が可能な水準）＝ A（一日信用）でショートを足してフル戦略**へ拡張し、
   down レジームの稼ぎ頭を回収。
3. **ハイブリッド**：ロングは端株で広く、ショートは一日信用で売り禁以外の主力数銘柄だけ——も可（口座2つ・運用は複雑）。

## 数値で確定するには（実データ前提）
```bash
python scripts/run_oc_cost_compare.py --capital 2000000   # A/B の手数料込みネット比較
python scripts/run_oc_longonly.py                         # both vs long vs short の SR/年率分解
```
比較の決め手：**A（単元+一日信用 両建）のネットSR/年率** と **B（端株 long-only, 0円）のネットSR/年率** を並べ、
「ショートの取り分」と「分散・低リスク・0円」のどちらが勝つかをデータで判定する。

> 手数料・約定仕様・信用の金利/貸株料・各社規約は改定されうる。発注前に必ず最新を確認すること。
